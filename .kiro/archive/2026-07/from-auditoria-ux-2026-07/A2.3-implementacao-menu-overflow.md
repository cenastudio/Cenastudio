## Decisões técnicas

### Por que não migrar para ResponsiveTabs?

`ResponsiveTabs` foi projetado para abas com conteúdo renderizado localmente (via `<TabsContent>`), não para navegação entre rotas.

**Problemas da migração:**
1. ResponsiveTabs usa API de Tabs do Radix UI (baseada em `value`, não em `href`)
2. Seria necessário refatorar ResponsiveTabs para suportar routing
3. CommercialHub renderiza componentes diferentes baseado em routing (não em estado local)
4. Maior risco de regressão e maior esforço

**Benefício do menu overflow:**
1. Mantém navegação por routing intacta
2. Segue padrão já validado (ProductionNav)
3. Menor mudança, menor risco
4. Atende todos os requisitos (≤2 toques, WCAG, descobribilidade)

### Por que 3 primary + 2 secondary?

**Análise de uso:**
- Overview, Clients, Pipeline: áreas mais acessadas diariamente
- Propostas, Interações: acessadas com menos frequência

**Priorização:**
- Primary tabs: sempre visíveis, 1 toque
- Secondary tabs: 2 toques (dropdown "Mais")

**Alternativa considerada:** 2 primary + 3 secondary
- Rejeitada: Pipeline é área de alto uso, deve estar sempre visível
