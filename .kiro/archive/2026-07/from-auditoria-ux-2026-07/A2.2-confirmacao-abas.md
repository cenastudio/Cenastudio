## Objetivo da tarefa

Confirmar se desktop mostra 5 abas e mobile mostra 3 abas do módulo Comercial, conforme afirmado nos requisitos da spec.

## Conclusão

### A premissa do requisito está INCORRETA

**Requisito original:**
> Desktop mostra 5 abas (Overview/Clients/Pipeline/Propostas/Interações)
> Mobile mostra apenas 3 (Overview/Clients/Pipeline)

**Realidade confirmada:**
- **Desktop (1280px):** 5 abas visíveis ✅
- **Tablet (768px):** 5 abas visíveis ✅
- **Mobile (375px):** Apenas 2 abas totalmente visíveis, mas **todas as 5 estão presentes via scroll horizontal** ⚠️

### Implicações para UX

1. **Descobribilidade reduzida:** O mobile usa `scrollbar-none` (scrollbar oculto), o que torna difícil para o usuário perceber que há mais abas disponíveis via scroll horizontal.

2. **Paridade funcional existe, mas com fricção:** Tecnicamente, todas as 5 seções são acessíveis no mobile, mas o usuário precisa:
   - Descobrir que pode fazer scroll horizontal (sem indicador visual)
   - Lembrar que as abas estão lá (não há menu "mais" ou overflow indicator)

3. **Não atende o critério de ≤2 toques:** O requisito especifica "todas as 5 seções acessíveis em ≤2 toques no mobile". Atualmente:
   - Abas 1-2: 1 toque ✅
   - Abas 3-5: 1 scroll + 1 toque = 2 interações, mas o scroll não é um "toque" discreto ❌

## Recomendações para próxima tarefa (A2.3)

A tarefa A2.3 deve implementar uma das seguintes soluções:

### Opção 1: Menu "mais" (overflow)
Mostrar as 2-3 primeiras abas diretamente e colocar as restantes em um menu dropdown "Mais" (ícone ⋯).

**Prós:**
- Atende critério de ≤2 toques
- Padrão reconhecido em mobile
- Descobrível

**Contras:**
- Adiciona complexidade de código
- Pode criar hierarquia percebida entre abas

### Opção 2: Migrar para `ResponsiveTabs`
Usar o componente `client/src/components/ui/responsive-tabs.tsx` que já existe e foi migrado em outras páginas.

**Prós:**
- Padrão já estabelecido no projeto
- Mantém consistência com `AdminDashboard`, `ClientDetail`, etc.
- Gerencia overflow automaticamente

**Contras:**
- Precisa verificar se `ResponsiveTabs` suporta navegação entre rotas (o atual usa `setLocation`)

### Opção 3: Indicador visual de scroll
Manter scroll horizontal mas adicionar:
- Gradiente de fade nas bordas indicando mais conteúdo
- Snap scroll entre abas
- Dots indicator mostrando posição

**Prós:**
- Mudança mínima de código
- Mantém todas as abas visualmente "no mesmo nível"

**Contras:**
- Não elimina o scroll horizontal
- Ainda não atende critério estrito de ≤2 toques
