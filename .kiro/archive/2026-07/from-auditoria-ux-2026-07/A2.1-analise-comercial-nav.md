## Componente identificado

## Estrutura atual

### Definição das abas

O componente define 5 abas no array `COMMERCIAL_TABS`:

```typescript
const COMMERCIAL_TABS = [
  { href: "/commercial",    labelPt: "Visão geral", labelEn: "Overview",     icon: BarChart3     },
  { href: "/clients",       labelPt: "Clientes",    labelEn: "Clients",      icon: Users         },
  { href: "/pipeline",      labelPt: "Pipeline",    labelEn: "Pipeline",     icon: GitBranch     },
  { href: "/proposals",     labelPt: "Propostas",   labelEn: "Proposals",    icon: FileText      },
  { href: "/interactions",  labelPt: "Interações",  labelEn: "Interactions", icon: MessageSquare },
] as const;
```

### Implementação de navegação

- **Tipo:** Implementação manual com `<nav>` e `<button>` elements
- **Responsividade:** Usa `overflow-x-auto scrollbar-none` para scroll horizontal
- **Não usa:** `ResponsiveTabs` component
- **Mobile:** Todas as 5 abas são renderizadas e visíveis via scroll horizontal

### Classe CSS aplicada

```tsx
<div className="flex items-center overflow-x-auto scrollbar-none">
  {COMMERCIAL_TABS.map((tab) => { /* ... */ })}
</div>
```

### Arquivos que usam CommercialNav

1. `/client/src/pages/CommercialHub.tsx` — Hub principal do módulo
2. `/client/src/pages/ClientDetail.tsx` — Página de detalhe de cliente

## Status de conformidade com os requisitos

### ❌ Não conforme

**Requisito:** "Criar menu 'mais' (overflow) ou migrar para padrão ResponsiveTabs"

**Situação atual:**
- Não há menu "mais" (overflow menu) para abas que não cabem
- Não usa `ResponsiveTabs` component (que já existe em `client/src/components/ui/responsive-tabs.tsx`)
- Usa scroll horizontal sem indicação visual clara de que há mais conteúdo

**Problema identificado:**
Em telas mobile pequenas, as 5 abas podem não ser imediatamente descobríveis porque:
1. Não há indicação visual de que há scroll horizontal disponível
2. O scrollbar está oculto (`scrollbar-none`)
3. Não há sombras ou gradientes indicando conteúdo fora da viewport

### ✅ Pontos positivos

- Todas as 5 abas estão tecnicamente acessíveis (podem ser acessadas por scroll)
- Ícones são usados para ajudar na identificação visual
- Implementação é semanticamente correta (usa `<nav>` e `role` implícito)
- Suporta internacionalização (PT/EN)

## Comparação com ResponsiveTabs

O componente `ResponsiveTabs` existente oferece:
- ✅ Altura mínima garantida (44px - WCAG 2.5.5)
- ✅ Scroll horizontal automático
- ✅ Suporte a contador de itens
- ✅ Estado ativo padronizado
- ✅ Classes CSS consistentes com design system

**Diferença chave:** `ResponsiveTabs` usa a API do Radix UI `<Tabs>`, enquanto `CommercialNav` usa navegação via roteamento (`wouter`).

## Recomendações para A2.2

Duas opções viáveis:

### Opção 1: Migrar para ResponsiveTabs (requer adaptação)
- **Prós:** Reutiliza componente padronizado, consistência com outras páginas
- **Contras:** ResponsiveTabs não foi feito para navegação entre rotas (usa `TabsContent` interno)
- **Esforço:** Médio-alto (requer refatoração de ResponsiveTabs ou criar wrapper)

### Opção 2: Adicionar overflow menu ao CommercialNav atual
- **Prós:** Menor mudança, preserva navegação por roteamento
- **Contras:** Não aumenta consistência com outras páginas migradas
- **Esforço:** Médio (adicionar dropdown com abas 4-5 em mobile)

### Opção 3: Melhorar indicação visual do scroll horizontal (quick win)
- **Prós:** Mínima mudança, sem regressão
- **Contras:** Não resolve totalmente o problema de descobribilidade
- **Esforço:** Baixo (adicionar gradiente/sombra lateral)

## Critério de aceite do requisito
